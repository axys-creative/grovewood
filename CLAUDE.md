# grovewood

SvelteKit (Svelte 5 runes, TypeScript) + SCSS + JSON content, edited through Decap CMS, hosted on Netlify. Package manager is bun. Built from the axys-template; unused template features were deleted, so anything not listed here can be re-added from the template on request.

## Rules

- **Deletable features.** A component, attachment or feature owns its JS and CSS. Nothing global may import it by side effect. Removal is: delete the file, delete its imports.
- **Styles.** Component styles live in the component's `<style lang="scss">` with plain class names (Svelte scopes them). Use `@use 'base/mixins';` for mixins. Global SCSS in `src/styles/base/` holds tokens, resets and shared utility classes, and uses BEM (`animate`, `animate--in`).
- **Tokens.** Colors, fonts and spacing are CSS custom properties in `base/_variables.scss`; the light theme is the `light-tokens` mixin. Theme is `data-theme` on `<html>`, set by the inline script in `app.html`.
- **Theme surfaces.** `theme-dark`, `theme-light` and `theme-invert` (in `base/_utils.scss`) give a section or wrapper its own theme by setting every themed token plus `background` and `color`. `theme-invert` is always the opposite of the page theme.
- **Accent colors.** Text and icons on an accent background use `--color-on-accent` (a fixed color in both themes), never `--color-text`. Outline, underline and text buttons have no fill, so their text follows the theme.
- **Behavior.** Reusable DOM behavior is an attachment (`{@attach fn(options)}`) in `src/lib/attachments/`, one file per behavior, with typed options. An attachment that needs CSS imports its own SCSS (`import './name.scss'`). Never read `window`, `document` or `innerWidth` at module scope (the module also loads during SSR); read them inside the attachment. Keep files alphabetical; related ones share a prefix (`text-*`). Component-specific behavior stays inside the component.
- **Heavy libraries.** GSAP and its plugins load through dynamic `import()` from `src/lib/utils/gsap.ts` (`loadGsap('scrollTrigger')`); call it from an attachment, never at module scope. The scroll-driven `text-*` attachments (reveal, scale) share `utils/text-scroll.ts` (ScrollTrigger + SplitText) and `attachments/text-split.scss`. Prefer CSS or `IntersectionObserver` when they are enough. Nothing touches `window` or `document` during SSR; use `onMount` or attachments.
- **Smooth scroll.** Lenis lives only in `components/smooth-scroll.svelte`, mounted once in `routes/(site)/+layout.svelte`. Add `data-lenis-prevent` to any element that must scroll natively (modals, inner scroll areas). It resets Lenis to the top after every navigation.
- **Page transitions.** A transition is an entry in `utils/page-transition.ts`. `components/page-transition.svelte` plays it on real navigations through `onNavigate` and view transitions (mounted once in the site layout with `fade`). `preserveHeader` keeps the header on screen by giving it a `view-transition-name` only during the change.
- **Scribble.** `attachments/scribble.ts` (with `scribble.scss` and `utils/scribble.ts`) draws a hand-drawn `underline` or `circle` on anything: shown from the start, on `hover`, or on `scroll`. Used by the rich-text `scribble` classes.
- **Alerts.** `alerts.show({ type, title, message, autoClose })` (`utils/alerts.svelte.ts`) puts an alert on screen from anywhere; `components/alert-stack.svelte`, mounted once in the site layout, stacks them.
- **Booking.** `components/calendar-booking.svelte` (content in `content/global/booking.json`, rules in `utils/booking-rules.ts`) is the booking popover, backed by `routes/api/availability`, `routes/api/book` and `lib/server/booking.ts` (Netlify Blobs, Resend). Netlify finds the form through `static/booking-form.html`, so keep its name and fields in step with the code. Step 3 has `show*` toggles for the name, email and phone fields (the one place the CMS toggles things); `lib/server/booking.ts` ignores and stops requiring a hidden field.
- **Header and footer.** One header (`components/header-simple.svelte`) and one footer (`footer-simple.svelte`), mounted in the site layout. The header's links and buttons are `content/global/navigation.json`; its style is `header-simple.json`; `site-nav.svelte` is the small-screen navigation.
- **Current page.** A link to the current page gets `aria-current="page"` and does nothing when clicked (the open nav still closes). `button.svelte` and `logo.svelte` do this through `utils/current-page.ts`.
- **Sections.** Every section takes an `id`; its Decap file's `preview_path` is `#id` (or `page#id` off the home page, since Decap joins `site_url`, a slash and the path). Every section takes a `fullScreen` boolean: at least `100lvh` with its content centered, and taller content still grows past it (never a fixed `height`). Heroes default it to `true`; other sections `false`. A scroll-driven section that needs a preview takes a `static` prop that skips its scroll and entrance animation; the preview registry sets `static: true`.
- **Section copy.** Every section that opens with an eyebrow, title, description and buttons uses `components/section-copy.svelte`, never its own markup. Spacing between those pieces comes only from `--space-eyebrow-title`, `--space-title-paragraph` and `--space-paragraph-cta-group`; use its `layout`, `align` and `show*` props instead of hiding pieces with CSS.
- **Rich text.** Plain text fields from the CMS never hold HTML. `utils/rich-text.ts` (`richText`) turns `[words]{.primary .scribble}` and `{.br}` into safe HTML (everything else is escaped), and `components/rich-text.svelte` renders it, with `attachments/rich-text.ts` running behavior classes (`scribble`) on the result. Render CMS text through `<RichText>`, never `{@html}`. Class names are shared across every client site and documented at axyscreative.com/tokens (the CMS hints point there), so keep them generic and update that page whenever the list changes. To add a class, add it to `richTextClasses`, and its CSS in `attachments/rich-text.scss` or a line in the attachment's `behaviors`.
- **Images.** Pictures go through Netlify's Image CDN on Netlify builds (`utils/image.ts`): spread `{...imageProps(src, { sizes })}` on the `<img>`, and set `sizes` to how wide the picture is actually drawn. Local dev keeps the original files; set `IMAGE_CDN=off` in the Netlify build environment to switch the CDN off. SVG, GIF and other sites' pictures are left alone. The main picture on a screen also gets `loading="eager"` and `fetchpriority="high"`. Uploads in the admin are capped at 8 MB (`capUploads` in `routes/admin/+page.svelte`). Share images (`seo.svelte`) are served as a 1200 by 630 JPEG.
- **Full-width sections.** `.page-grid` (in `base/_utils.scss`) lays a page out on three columns: children sit in the middle column, limited to `--content-width` with `--body-padding` at the edges, and a child with the class `full` runs edge to edge. It uses grid lines, not `100vw`, so it never adds sideways scroll.
- **Top layer.** `<dialog>`s sit above everything. Prefer native elements (`details`, `dialog`, `popover`, `button`).
- **Accessibility and motion.** Every animation respects `prefers-reduced-motion`. Interactive elements are keyboard-operable with visible focus, correct roles and accessible names.
- **Pages and SEO.** Page titles, descriptions and share images are in `content/meta/pages.json`, read by `seo.svelte`; a page missing from it is indexable with the site defaults. `crawlPage: false` adds `noindex`. The sitemap lists the pages with `crawlPage: true`. Site-wide values are `content/meta/site.json`.
- **Content.** Each section reads one JSON file in `src/lib/content/`. Its Decap fields in `src/routes/admin/config.json` must match that file's shape, and its props are typed in the component. No show/hide toggles in the CMS; an empty field renders nothing (the `show*` props on `section-copy` are a developer API). `eyebrowIcon` is an `image` field: an SVG path starting with `/` is drawn as a mask in the eyebrow color. To hide a Decap collection without deleting it, add `"hide": true` to it.
- **Decap previews.** Previews mount the real Svelte components, so there is one copy of the markup. Runtime-only state (classes added by actions) must not hide content in the preview. `routes/admin/previews.ts` holds the registry, keyed by the file's `name` in `config.json` (files that share a name share an entry; give one a unique name if its props differ). A new section needs an entry whose `props` mirrors what its page passes and defaults every required list or object (`?? []`, `?? {}`), because the entry can arrive empty. `preview-host.svelte.ts` mounts it with reactive props. Only sections, the simple header and the simple footer are previewed (those entries merge `navigation.json`, `logo.json` and `social-media.json` into their props). The Global collection turns previews off, so those two files opt back in with `"editor": { "preview": true }`. Attachments run against the admin window, so test scroll-driven sections.
- **Admin view controls.** `routes/admin/view-controls.ts` adds a button next to Decap's preview and scroll-sync buttons that moves them to the preview pane's left edge and back (remembered in `localStorage`). Decap's classes are hashed, so it matches the stable emotion labels (`-ViewControls`, `-PreviewPaneFrame`), never the hash. To remove it, delete the file and its import, call and cleanup in `routes/admin/+page.svelte`, and the two view-controls blocks (and `@keyframes view-controls-in`) in `routes/admin/admin.scss`.
- **Dev.** `bun dev`, plus `bun run cms` (decap-server, for `local_backend`) in a second terminal to use `/admin` locally; without it every field loads empty. Vite compiles SCSS, so there is no Sass step. Run `bun run check` and `bun run lint` before finishing.
